========================================================================
MooTrack360 カメラキャリブレーション & BEV変換 パイプライン README
========================================================================

このディレクトリには、魚眼カメラ(Double Sphere モデル)のキャリブレーションから
牛の位置をBEV(鳥瞰図)に変換するまでの一連の作業に使う3つのスクリプトがある。

  1. calibrate_camera2.py  ... カメラ1台ずつの位置・姿勢・内部パラメータを求める
  2. make_camera_viz.py    ... 求めたパラメータが実画像に合っているか目視確認する
  3. make_bev.py           ... 求めたパラメータを使って牛の位置をBEVに変換する

3つは「求める→確認する→使う」の一連の流れになっており、
calibrate_camera2.py の出力を make_camera_viz.py / make_bev.py にコピペして使う。


------------------------------------------------------------------------
1. calibrate_camera2.py (較正スクリプト)
------------------------------------------------------------------------

【何をするスクリプトか】
任意の1台のカメラについて、次の2種類のペア情報をもとに、
実世界とのズレを最小化するように較正済みパラメータを求める。

  (a) 実画像上のピクセル座標
      合成画像の左上を原点(0,0)としたときの、対象カメラのタイル内
      ローカルピクセル座標(0〜2944)。
      例: Wall_12 の top の角、Gate_1 の left の角 など、
          floorplan.json の semantic_regions に載っている頂点で、
          画像内でも位置が特定しやすい「角」を選ぶ。

  (b) 対応する実世界座標(メートル)
      floorplan.json の polygon_world_meters の中から、(a)のピクセルが
      指している頂点と同じものを探して対応させる。

このピクセル座標<->実世界座標のペア(REFERENCE_POINTS)を4〜6点用意して
scipy.optimize.least_squares で最適化すると、次の3パターンの
較正済みパラメータが得られる:

  - 回転のみ         : 位置は元のまま、回転(a,b,c)だけ調整
  - 回転+位置        : 位置(px,py,pz)と回転(a,b,c)の両方を調整
  - 回転+位置+内部パラメータ: 上記に加えて DS モデルの xi, alpha も調整

【使い方】
  1. CAM_ID / PARENT_ID を較正したいカメラに設定する
     (Camera_1なら親はArea1、Camera_2なら親はCamera_1、Camera_3なら親はCamera_2)
  2. KNOWN_OVERRIDES / KNOWN_INTRINSICS_OVERRIDES に、
     "すでに較正済みの他カメラ" の値を入れておく
     (カメラは必ず Camera_1 -> Camera_2 -> Camera_3 の順で較正すること。
      親の位置が子の計算の土台になるため、親を先に確定させる必要がある)
  3. REFERENCE_POINTS に、対象カメラの基準点(ピクセル座標+実世界座標)を入力する
  4. 実行すると、3パターンそれぞれの最適化前後の誤差(メートル)が表示される

【出力の見方・注意点】
  - 基準点1点あたりの誤差が全体的に小さくなっていれば較正成功
  - 特定の1点だけ大きく誤差が残る場合、その点の対応関係(ピクセル座標か
    world座標)が間違っている可能性が高い -> その点を疑って確認し直す
  - xi(内部パラメータ)が探索範囲の境界(±0.05等)にぴったり張り付く場合は
    要注意。過学習(意味のない解)のサインであり、範囲を広げてもさらに
    境界に張り付き続けるなら、その最適化結果は採用しないこと
    (実際に Camera_1, Camera_3 ではこの理由で内部パラメータの変更を見送った)
  - 基準点は画角の周辺(壁やゲートの角)に偏りやすい。牛がいる中間領域の
    精度を保証するものではない点に注意。可能なら牛がいる領域に近い
    基準点も混ぜること


------------------------------------------------------------------------
2. make_camera_viz.py (較正前後の目視確認スクリプト)
------------------------------------------------------------------------

【何をするスクリプトか】
calibrate_camera2.py で求めたパラメータを、実際の魚眼画像に重ねて
目視確認するためのスクリプト。frloorplan.json の semantic_regions
(壁・ゲート・給餌エリア等のポリゴン)を World -> カメラ画像 方向に
逆投影してオーバーレイする。

  - 較正前(floorplan.json のオリジナル値)
  - 較正後(CAMERA_PARAM_OVERRIDES / CAM_INTRINSICS 適用後)

の両方の画像を自動生成し、左右に並べた比較画像(*_before_after.png)も
保存するので、境界線が実画像にどれだけ合っているか一目で比較できる。

【使い方】
  1. CAMERA_PARAM_OVERRIDES / CAM_INTRINSICS に、
     calibrate_camera2.py で求めた値をそのままコピペする
     (空 {} にすると「較正前」の状態のみ出力される)
  2. 実行すると、カメラごとに次のファイルが生成される:
       overlay_cam{N}_before.png       較正前のオーバーレイ
       overlay_cam{N}_after.png        較正後のオーバーレイ
       overlay_cam{N}_before_after.png 左右に並べた比較画像
       farm_bev_map_before_after.png   BEV上でのカメラ位置比較

【使い方のコツ】
  - calibrate_camera2.py の基準点フィッティング誤差(数値)だけでなく、
    この目視確認を必ずセットで行うこと。数値上は改善していても、
    画像で見ると別の場所(牛のいる中間領域など)がズレて見えることがある
  - 複数の較正パターンを試すときは、CAMERA_PARAM_OVERRIDES の中身を
    書き換えて再実行するだけで比較できる


------------------------------------------------------------------------
3. make_bev.py (本番: 牛の位置をBEVに変換するスクリプト)
------------------------------------------------------------------------

【何をするスクリプトか】
annotation.xml に記録された牛のバウンディングボックスを、較正済みの
カメラパラメータを使って実世界座標(BEV)に変換し、画像・CSVとして出力する。

  1. floorplan.json からカメラの位置・姿勢を解決
     (CAMERA_PARAM_OVERRIDES / CAM_INTRINSICS で上書きされた値を使う)
  2. bbox から「接地点(牛の足元にあたるピクセル)」を求める
     FOOT_POINT_METHOD で2方式を切替可能:
       - "gamma"  : 角度ベース+CURVE_GAMMAの経験的ヒューリスティック(旧方式)
       - "relief" : bboxの近い隅=床面(z=0)、遠い隅=牛の背の高さ
                    (z=-COW_HEIGHT_M)とみなし、それぞれ逆投影して平均する
                    視差補正(relief displacement)方式。牛の体高という
                    物理的に意味のある1パラメータだけで済む(推奨)
  3. Double Sphere モデルで接地点ピクセルを実世界座標(x,y)に逆投影
  4. 同一牛が複数カメラに写っている場合は平均して1点にまとめる
  5. BEV画像・カメラ別BEV画像・CSVを出力

【出力ファイル】
  bev_cow_positions.png              牛の位置を描画したBEV画像(最終結果)
  bev_cow_positions.csv              牛ごとの座標一覧
  bev_cow_positions_per_camera.png   カメラ別の投影結果(平均前)。
                                      視点ごとのズレを可視化する
  bev_cow_positions_per_camera.csv   カメラ別の座標とズレ量
  gamma_sweep_results.csv            CURVE_GAMMAを振った時の一致度比較
  relief_sweep_results.csv           COW_HEIGHT_Mを振った時の一致度比較

【評価指標(dist_from_mean_m)の意味・注意点】
  gamma_sweep / relief_sweep で使う「誤差」は、実世界の正解座標との比較
  ではなく、「同じ牛を複数カメラで見たときの、各カメラの推定座標と
  その平均座標とのズレ」である(=カメラ間の相対的な一致度)。
  全カメラが同じ方向に system的にズレていても、この指標は改善して
  見えてしまう点に注意。calibrate_camera2.py の基準点フィッティング誤差
  (絶対誤差)とは別の指標であり、両方をセットで確認すること。


------------------------------------------------------------------------
推奨の作業フロー
------------------------------------------------------------------------

  1. calibrate_camera2.py で Camera_1 を較正する(親はArea1)
  2. make_camera_viz.py で Camera_1 の較正前後を目視確認する
  3. calibrate_camera2.py で Camera_2 を較正する
     (KNOWN_OVERRIDES に較正済みCamera_1の値を必ず入れる)
  4. make_camera_viz.py で Camera_1+Camera_2 の較正前後を目視確認する
  5. calibrate_camera2.py で Camera_3 を較正する
     (KNOWN_OVERRIDES にCamera_1・Camera_2両方の値を必ず入れる)
  6. make_camera_viz.py で3台まとめて目視確認する
  7. make_bev.py の CAMERA_PARAM_OVERRIDES / CAM_INTRINSICS に
     最終的な較正値を反映し、FOOT_POINT_METHOD="relief" で実行する
  8. gamma_sweep / relief_sweep の結果と、bev_cow_positions_per_camera.png
     を見て、絶対誤差(基準点)と相対誤差(カメラ間一致度)の両方を確認する
  9. 気になるカメラ・領域があれば 1. に戻って基準点を追加し再較正する

※ 親カメラのパラメータを変更すると、そのカメラを親とする子カメラの
   計算結果も変わるため、Camera_1を較正し直した場合はCamera_2・Camera_3も
   同じ土台の上で必ず再計算すること。
